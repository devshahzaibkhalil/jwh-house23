JAMES WHOLESALE HOMES CHATBOT - EMAIL SETUP (RESEND API)
==========================================================

This app sends all emails (owner lead notifications, customer
confirmations, verification codes) through the Resend HTTPS API instead of
SMTP. This is required for hosts like Render, which block outbound SMTP
ports 25/465/587 on free instances and block port 25 entirely even on paid
instances. An HTTPS API call is unaffected by that restriction.

1. CREATE A RESEND ACCOUNT
---------------------------
1. Go to https://resend.com and sign up (a free tier is available).
2. Go to https://resend.com/api-keys and click "Create API Key".
3. Copy the key - it looks like: re_XXXXXXXXXXXXXXXXXXXXXXXXXXXX
   You will not be able to view it again after closing the dialog.

2. VERIFY A SENDING DOMAIN (RECOMMENDED FOR PRODUCTION)
---------------------------------------------------------
1. Go to https://resend.com/domains and click "Add Domain".
2. Enter a domain you own, e.g. yourdomain.com.
3. Add the DNS records Resend gives you (SPF, DKIM, and optionally DMARC)
   at your domain registrar or DNS provider.
4. Wait for the domain status to show "Verified" (usually a few minutes,
   sometimes longer depending on DNS propagation).
5. Once verified, you can send from any address at that domain, e.g.
   noreply@yourdomain.com.

   Skipping this step: Resend also gives every account a shared testing
   address (onboarding@resend.dev) that works immediately with no DNS
   setup, but it can only send to the email address on your Resend
   account and is not suitable for real leads. Verify your own domain
   before going live.

3. CONFIGURE THE APP
----------------------
Local development (.env file):
   RESEND_API_KEY=re_your_real_key_here
   MAIL_DEFAULT_SENDER=noreply@yourdomain.com
   MAIL_SENDER_NAME=James Wholesale Homes
   OWNER_EMAIL=you@example.com

Render (dashboard -> your service -> Environment):
   Add the same four variables above. render.yaml already declares
   RESEND_API_KEY, MAIL_DEFAULT_SENDER and OWNER_EMAIL as
   "sync: false" placeholders, so Render will prompt you for their
   values during the Blueprint setup.

4. TEST DELIVERY
------------------
From the project root, with your virtual environment active:
   python test_email.py

This sends a plain test email to OWNER_EMAIL using the Resend API and
prints "Test email sent to ..." on success, or the API error message on
failure. A delivery record is also written to the EmailLog table, visible
from Admin -> Security Centre in the dashboard.

5. COMMON ERRORS
-------------------
"RESEND_API_KEY and MAIL_DEFAULT_SENDER are required"
   One or both env vars are missing. Check .env locally, or the Render
   Environment tab in production.

"Resend API error 403: ..." / "domain is not verified"
   MAIL_DEFAULT_SENDER uses a domain that has not been verified in
   Resend yet (step 2), or you are sending to an address other than
   your own account email while still using the onboarding@resend.dev
   testing sender.

"Resend API error 401: ..."
   The API key is missing, revoked, or mistyped.
